Good queries get better, more verifiable answers. Use these patterns in **Search** or **Work**.

## Core pattern

**Type + key params + constraints + context**

```
Need an N-channel MOSFET, ≥60V, ≥20A, TO-220, for 12V motor drive, industrial temp
```

## Do / Don't

| Prefer | Avoid |
| --- | --- |
| Exact MPN when you have it (`STM32F103C8T6`) | “a microcontroller” |
| Numbers with units (`3.3V`, `1A`, `SOT-23`) | “small and cheap” only |
| Application constraints (`4.5A USB charge`, `automotive`) | No use-case when asking for alternatives |
| One goal per ask | Mixing five unrelated asks |

## Query recipes

**Lookup / specs**

```
STM32F103C8T6 operating voltage and absolute maximum ratings
```

**Alternatives** (expect clarification on constraints)

```
Alternative to BQ24195 for 4.5A USB charging, VQFN preferred
```

**Work / BOM**

```
Analyze top risks from this BOM and suggest adopts for NRND lines
```

**Tariff**

```
Check tariff for 74HC595 made in China entering the US
```

## After the answer

- Click **citation badges** to verify
- For substitutes, confirm or skip the constraint card—context improves fit
- Attach Knowledge files when the ask depends on *your* schematic or app note
